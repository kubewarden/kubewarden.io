Why SBOM Scanner?

Scan images, workloads and nodes

One tool for registries, what is actually running, and the hosts underneath.

SBOM first

Build the bill of materials once, then keep re-checking it as new vulnerabilities are published.

Kubernetes-native

Registries, scans and reports are Kubernetes resources. Query them with kubectl.

Enforce with Kubewarden

Block vulnerable images at admission with the image-cve policy.

Built for the people doing the work

For platform teams

Know what runs in your cluster, and what is wrong with it.

  • Scan whole registries or only the images your workloads use
  • Schedule scans, or run them on demand
  • Cover the nodes, not just the containers
  • Cut false positives with VEX statements
registry.yaml
apiVersion: sbomscanner.kubewarden.io/v1alpha1
kind: Registry
metadata:
  name: my-registry
  namespace: default
spec:
  uri: ghcr.io
  scanInterval: 1h
  repositories:
    - name: kubewarden/sbomscanner

For security teams

Turn findings into decisions.

  • Query SBOMs and reports with kubectl
  • Filter by registry, repository, tag or severity
  • Block vulnerable images at admission with Kubewarden
  • Works in air-gapped and private-registry setups
kubectl
# Filter by severity
kubectl get vulnerabilityreport -n default \
  --field-selector spec.severity=Critical

# Inspect a single report
kubectl describe vulnerabilityreport <name> -n default
Learn about querying reports (opens in new tab)

Ready to try it?

Install SBOM Scanner with Helm and start scanning your first registry.

# Requires cert-manager and CloudNativePG - see the quickstart
helm repo add kubewarden https://charts.kubewarden.io

helm install sbomscanner kubewarden/sbomscanner \
  --namespace sbomscanner --create-namespace \
  --set controller.replicas=1 --set storage.replicas=1 \
  --set storage.postgres.cnpg.instances=1 --set worker.replicas=1 \
  --wait
